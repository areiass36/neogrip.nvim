1. INTRODUCTION                                 *neogrip-introduction*

Neogrip turns Neovim into a SQL and data-manipulation client: pick which
database a file runs against, run the statement under the cursor, read the
result in a grid, and query that result again with SQL through DuckDB.

A Lua plugin talks JSON-RPC over stdio to gripd, a small Java daemon that
speaks JDBC to the databases. The plugin downloads its own pinned,
checksum-verified JDK and driver jars on first use and compiles gripd from the
sources in the repository - nothing to install.

Engines: PostgreSQL, MySQL/MariaDB, SQL Server, Azure SQL, Trino, MongoDB,
SQLite and DuckDB.

==============================================================================
2. REQUIREMENTS                                 *neogrip-requirements*

- Neovim 0.12 or newer.
- kvstore.nvim (https://github.com/areiass36/kvstore.nvim): every secret is
  read from it and from nowhere else. Store one with `:KVStore <key>`.
- Optional: nvim-cmp (a completion source), jq (pretty printing of Mongo
  documents). A schema explorer is yours to build - see |neogrip-tree| and the
  worked example in doc/explorer-recipe.md - so whichever picker or tree
  plugin you already use is the one that draws it.

==============================================================================
3. SETUP                                        *neogrip-setup* *neogrip.setup()*

`require("neogrip").setup(opts)` is the single entry point; the plugin does
nothing before it is called, and downloads nothing until the first connect.
With lazy.nvim: >lua
    {
      "areiass36/neogrip.nvim",
      dependencies = { "areiass36/kvstore.nvim" },
      opts = {},
    }
<

4. CONNECTIONS                                  *neogrip-connections*

Connections live in `.nvim/database.json` at the project root (and a global
file under |stdpath|("state")); `:NGripInit` writes a starter. Schema v2: >json
    {
      "version": 2,
      "default": "replica",
      "connections": [
        {
          "id": "replica",
          "name": "Transactional (replica)",
          "driver": "postgres",
          "host": "db.example.com",
          "port": 5432,
          "database": "app",
          "readonly": true,
          "production": true,
          "auth": {
            "type": "password",
            "user": "fulano",
            "password": { "kvstore": "replica-password" }
          }
        }
      ],
      "bindings": [
        { "glob": "db/migrations/**/*.sql", "connection": "replica" }
      ]
    }
<
Every secret-bearing field must be a `{ "kvstore": "<key>" }` reference; a
literal value is a hard validation error. `auth.type` is one of `none`,
`password`, `token` (bearer, via the driver's accessToken property);
`entra_interactive`, `service_principal` and `managed_identity` are carried
by the schema and land in a later phase. Drivers: `postgres`, `mysql`,
`mariadb`, `mssql` (also `azuresql`), `sqlite`, `duckdb`, `trino`,
`mongodb` - file engines take `"file"` instead of host/port.

Which connection a buffer uses is resolved most-specific-first: an explicit
choice, a saved binding for the file, a glob from the project file, the
project default, the last one used. `:NGripWhich` explains the answer.

5. COMMANDS                                     *neogrip-commands*

:NGripRun [sql]        Run a statement, or the one under the cursor. A
                       visual selection runs every statement in it, in
                       sequence; the grid shows the last.
:NGripCancel           Cancel the running query - a real server-side cancel.
:NGripValidate         Check the statement on the server; nothing executes.
:NGripUse {id}         Use a connection in this buffer.
:NGripWhich            Which connection applies here, and why.
:NGripConnections      List the configured connections.
:NGripReload           Re-read the connection files.
:NGripIntrospect[!] [catalog]
                       Sweep the whole database into the on-disk catalog;
                       ! cancels a running sweep.
:NGripSchemaReload     Drop the cached catalog for this buffer's connection.
:NGripResults          Query the current result with SQL (DuckDB views
                       r1, r2, ... and the alias `last`).
:NGripCsv {file}       Query any CSV file with SQL.
:NGripExport           Export the result: CSV or JSON, page or everything.
:NGripKeep [file]      Write the page somewhere it will not be cleaned up.
:NGripNewQuery         A query buffer against this buffer's connection.
:NGripDisconnect[!] [id]
                       Stop a connection's gripd; ! stops every one.
:NGripInit             Write a starter .nvim/database.json.
:NGripDoctor           Check the JDK, gripd, drivers and connections.

6. GRID ACTIONS                                 *neogrip-grid*

The result buffer (filetype `neogrip-grid`) has no keymaps: every action is a
function on `require("neogrip.grid.actions")`, for the user to map (the
README carries a complete recipe).

  next_column  prev_column  down  up          movement, cell by cell
  first_column last_column  first_row last_row
  yank_cell    yank_row     yank_column       the stored value, untruncated
  sort_asc     sort_desc                      server-side, covers every page
  page_next    page_prev                      continues the open result
  follow_fk                                   open the row this key points at
  show_document                               the whole Mongo document
  export       materialise  close

Yanks and exports always read the stored value, never the drawn text: what is
on screen may be truncated.

A result stays open on gripd as a cursor, so `page_next` continues it
instead of running the statement again, and `page_prev` is a redraw of rows
that never left the editor. Sorting is the exception: the order has to be the
server's to cover every page, so it opens a new result. An open result is let
go when the grid shows another one, and after |neogrip-options|
`cursor_idle_seconds` of nothing asking for a page.

7. CATALOG TREE                                 *neogrip-tree*

The plugin draws no explorer (ADR-0037). It answers the catalog as data and
you draw it: `require("neogrip.tree")`.

Six levels, a closed set:

  server -> instance -> namespace -> set -> object -> attribute
  (conn)    (database)  (schema)    (table) (row)     (column)

Which of them a connection has differs by engine, and the plugin keeps that
knowledge: SQLite has no schemas, MySQL has databases but no schemas, Trino
calls a database a catalog, and a connection that names its database starts
below the level that chooses one.

                                                *neogrip.tree.shape()*
shape(connection)
        The walk this connection has, already truncated, as
        `{ levels = { { level, label, on_demand?, reconnects? } }, sweepable,
        cacheable_until }`. `label` is what to put in a header - "Collections"
        on MongoDB, "Catalogs" on Trino - so one renderer serves every engine
        without naming one. `object` is marked `on_demand`: rows are data,
        they cost a query and are never cached.

                                                *neogrip.tree.children()*
children(node, opts, callback)
        The children of `node`, at whatever level comes next. `node` of nil
        answers the configured connections, so one recursive function walks
        from there to a column. Returns a handle with `:cancel()` - abandon it
        when a node collapses; for rows that also closes the cursor on the
        server. `opts.objects = true` reaches the rows instead of the columns,
        with `limit`, `hash` and `from` to page and `on_page` to receive the
        continuation.

        A node is `{ id, level, kind, name, ref, expandable, source, facts }`
        and carries nothing formatted: no icons, no padding, no "12 columns".
        `kind` for a set is `table`, `view` or `collection` and nothing else.
        `source` is `"cache"` or `"server"`. `ref` is the whole path, always,
        and it names a connection by id - register an ephemeral one with
        `require("neogrip.connections").register()` first.

The rest are tools, not UI. None of them opens a buffer:

  qualified_name(ref)            the name as SQL, quoted for this engine
  statement(ref, kind, cb)       select|insert|update|delete, as text
  details(ref, cb)               keys, indexes and references for one set
  ddl(ref, cb)                   the server's own definition, or nil
  counts(ref, cb)                approximate row counts for a namespace
  find(ref, pattern, cb)         sets whose name matches, flat
  sweep(ref, opts, cb)           sweep the instance, or one namespace of it
  swept(ref)                     when it was swept and what it holds, or nil
  forget(ref)                    drop what is cached; the client decides when

`require("neogrip.render").details(connection, namespace, set, details)` turns
a details record into lines of SQL, if you want the definition the plugin used
to draw. `require("neogrip.icons")` is a table you may read or ignore.

Nothing watches the database: after a migration, the client calls `sweep` or
`forget` itself.

doc/explorer-recipe.md is a working explorer in about a hundred lines.

==============================================================================
8. LANGUAGE SERVICES                            *neogrip-lsp*

An in-process LSP server per connection answers from the catalog that
`:NGripIntrospect` swept: hover (K), document and workspace symbols (gO),
plus two functions to map yourself - `require("neogrip.lsp").definition()`
jumps to the object under the cursor and `.references()` lists its
foreign-key neighbours in the quickfix list. Completion is a separate
nvim-cmp source named `neogrip`; add `{ name = "neogrip" }` to your cmp
sources where you want it.

Saving a `.sql` buffer validates the statement on the server (nothing runs);
see |neogrip-options| `validate_on_save`.

==============================================================================
9. STATUSLINE                                   *neogrip-statusline*

`require("neogrip.statusline").component()` renders `replica [RO][PROD][TX]`
for the current buffer: read-only, production - the one effect
`production: true` has - and an open explicit transaction. `status(bufnr)`
returns the same facts as a table; `is_production(bufnr)` is the single flag.

==============================================================================
10. OPTIONS                                     *neogrip-options*

Defaults, overridable through `setup(opts)` (each is documented where it
lives, `lua/neogrip/config.lua`): >lua
    require("neogrip").setup({
      limit = 200,                   -- rows per result page
      cursor_idle_seconds = 300,     -- an open result nobody pages is closed
      timeout_ms = 30000,            -- server-side statement timeout (0 = none)
      max_column_width = 60,         -- grid truncation; yanks are whole
      null_text = "NULL",
      row_numbers = false,           -- number the rows down the page (gutter)
      stripe_rows = true,
      result_retention_days = 2,     -- orphaned result files
      schema_ttl_seconds = 3600,     -- per-question catalog cache
      introspect_parallelism = 4,    -- sweep connections
      introspect_details = true,     -- keys and indexes in the sweep
      validate_on_save = true,
      transaction_idle_seconds = 600,-- idle open tx is rolled back
      icons = {},                    -- database, folder, table, file, branch
    })
<
==============================================================================
11. HIGHLIGHTS                                  *neogrip-highlights*

Every group is defined with `default = true`, so your own |nvim_set_hl()|
wins. The grid's groups are prefixed `NGripGrid`: Header, HeaderSorted, Rule,
Separator, Stripe, Ellipsis, Cell, Null, Number, Boolean, Temporal, Uuid,
Json, Binary, Footer, Connection, Production, Count, Elapsed, Slow.

==============================================================================
12. LIMITATIONS                                 *neogrip-limitations*

- No confirmations for dangerous statements: `readonly: true` refuses writes
  in layers, `production: true` is a visible signal, and the strongest
  protection is a database user with read-only permissions.
- Secrets live in kvstore.nvim, nowhere else; the connection file holds only
  key names. An expired token fails the statement - nothing renews it
  silently; store a fresh value and `:NGripDisconnect`.
- Entra ID interactive, service principal, managed identity and SSH tunnels
  are declared in the schema but not implemented yet.
- MongoDB speaks the wrapper's script dialect, not SQL; collections have
  sampled fields, not columns, and that field sampling is best-effort - the
  third-party wrapper's metadata is unreliable (ADR-0029).
